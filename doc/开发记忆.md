# 开发记忆（Ktor 模板 → Kotlin/Native）

> 用途：**会话交接记忆**。换 session / 换设备后先读本文，再按需查详细方案。
> 详设与实测记录见 [native-migration-plan.md](./native-migration-plan.md)（§8 = P0/P1/P2 路线，§13 = 实施进度与踩坑）。
> 分支：`native`。所有内容以**实测**为准，未经验证的推断已剔除。

## 1. 项目概览

- 原本是 Ktor **JVM** 单体后端模板（`project-template`），现在整体迁往 **Kotlin/Native**，只产出**原生可执行文件**。
- 目标平台：**`mingwX64`**（Windows 本地开发调试）+ **`linuxArm64`**（部署到开发板）。**不保留 JVM 目标**。
- 旧 JVM 代码**整体移到 `legacy/`**（不参与编译，仅作移植参考）；`:orm` 模块与全部 JVM 插件/依赖已移除。
- 根包 **`moe.lolosia.web`**；独立 Gradle 模块 `:router-ksp`（包名保持 `moe.lolosia.router.ksp`，它是插件域，不受根包约束）。
- 配套前端工程：`F:\Develop\Node\lolosia-web`（Vue3 + Vite），已通过 `platforms.json` 的 `webPath` 接入构建。

## 2. 硬性约定（改动前必读，违反会返工）

1. **包归置**：`src/` 下代码一律 `moe.lolosia.web`。
   - 工具/脚手架进 `util.<域>`：`util.router`（注解+参数绑定+multipart）、`util.classpath`（资源访问）、`util.session`（上下文）
   - `controller/` 放控制器；`buildSrc` 的 Gradle 插件包名不受此限
2. **按类型自动注入（Spring 风格）**：控制器形参写 `ctx: Context`，**不加任何注解前缀**（曾有过 `@Attribute("ctx")`，已按要求移除）。
   路线：类型标 `@Injectable` → 启动时 `RouterInjection.register(类型) { call -> ... }` → KSP 生成 `call.inject<T>()`。
3. **注解参数名可省略**：`@Path` / `@Query` / `@Header` / `@Form` / `@FilePart` 不写名字时默认取形参名。
4. **资源一律走 `classpath` 中间层**，不要用文件系统路径：
   `src/<sourceSet>/resources/**` 就是 classpath 根，运行时 `classpath.read("static/home/index.html")`，与 Java 打资源文件完全一致。
5. **控制器跨项目复制的目标是"只改 import"** —— 注解同名同义，方法体零改动。
6. **`main()` 必须放各目标源集**：KSP2 在 KMP 下**没有 common/metadata 编译单元**，生成代码落在目标源集，而 common 代码看不到 platform 声明。故 common 提供 `startServer(port) { generatedRoutes() }`，各目标 `main()` 传入。
7. **KSP 聚合输出必须带源文件**：`Dependencies(aggregating = true, *sourceFiles)`。只写 `aggregating = true` 会导致增量处理漏扫未改动文件里的 `@Controller`，症状是**编译通过但接口全 404**。
8. **前端路径不许写死**：用 `generateConstants` 产出的 `VITE_DEFAULT`（值 = viteJar 的 `contextPath`）拼路由。
9. **构建/部署只有一个入口**：Windows 上 `gradlew deploy1m`（见 §5）。
10. **配置只认 `AppConfig` 一个入口**：`moe.lolosia.web.config.AppConfig`（`@Serializable` 数据类）。
    加载优先级（低→高）：数据类默认值 < classpath 内嵌 `src/commonMain/resources/application.json` < 磁盘 `application.json`（CWD，systemd 下 = `/srv/ktor-template/`）< 环境变量（`KTOR_HOST/PORT/LOG_LEVEL/DB_URL/DB_USERNAME/DB_PASSWORD`）；端口另可由命令行参数覆盖（最高）。
    各层按字段深合并。加配置项 = 改数据类 + 可能改 `envOverrides`，**不要另起一套读取逻辑**。
11. **日志一律走 `Log.of("tag")`**，不要 `println`；级别由配置 `logLevel` 控制。
12. **DI：Koin 容器显式传递，不要碰全局容器**。`startAppKoin(config, cp)` 返回 `Koin` 并向下传；
    容器里的实例用 `koin.registerInjectable<T>()` 接进路由「按类型注入」，控制器形参声明即得。
    ⚠️ Koin 4 里 `org.koin.core.context.GlobalContext` 与 `koinApplication` **不是公开 API**（native 上直接 Unresolved），只有 `startKoin { }.koin` 可用。
13. **数据层走 sqlx4k**（`db/` + `db/model/` + `service/`）：
    - 实体：`@Table("表名")` + `@Id`（DB 自增）/ `@Id(insert = true)`（应用给主键）；列名自动 snake_case。
    - 仓库：`@Repository` + `@Injectable`（**必须**，否则控制器形参注入会报「无法绑定」）+ `CrudRepository<T>`；
      **第一个参数必须是 `context: QueryExecutor`**、**方法必须 `suspend`**、**每个方法都必须带 `@Query`**
      （生成器只实现带 `@Query` 的方法，**没有派生查询**）。
    - 方法名白名单是**精确**的：`findAll` / `deleteAll` / `countAll`，或 `findAllBy*` / `findOneBy*` / `deleteBy*` /
      `countBy*` / `existsBy*` / `execute*`。`findAllActive`、`countAllByKeys` 这类都不合法（KSP 直接报错），
      返回类型由前缀决定：`findAllBy*`→`Result<List<T>>`、`findOneBy*`→`Result<T?>`、`countBy*`→`Result<Long>`、`execute*`→`Result<Long>`。
    - ⚠️ **不支持 `IN (列表)`**：`@Query` 的 SQL 在编译期就把 `:ids` 固定成一个 `?`，运行期没有展开机会
      （传 `List` 会被当单值绑定，服务端报 `Illegal parameter data types varchar and row for operation '='`）。
      批量场景在服务层**循环调用单条方法**。
    - 生成的实现是 `object XxxRepositoryImpl`（包 `moe.lolosia.web.db.generated`），**只存在于目标源集** → 在
      `src/{mingwX64,linuxArm64}Main/Main.kt` 的 `platformModules()` 里注册，再交给 `startServer(..., platformModules)`。
      生成物要能被注入，还得在 `Bootstrap.configureApplication` 里 `koin.registerInjectable<XxxRepository>()`。
    - ⚠️ **MySQL 方言下不要用 `CrudRepository` 自带的 `insert` / `update`**：生成器把它们拼成
      `insert ...; select ...` 多语句脚本，MariaDB 单语句预处理直接 `1064`。写入用仓库里的单语句 `@Query`
      （如 `executeInsert`）。`delete` 是单语句，可用。
14. **时间：库里时间列一律用 `kotlin.time.Instant`**（业务代码直接 `Clock.System.now()`），**不要用 `LocalDateTime`**。
    sqlx4k 对 `Instant` 全程按 UTC 编解码（`Instant.toTimestampString(TimeZone.UTC)` / `Column.asInstant()`，
    后者注释写明「没有偏移量就按 UTC 解释」），时区语义由**类型系统**保证，不需要任何「写库要用 UTC」的人工约定。
    （反面教材：用裸 `LocalDateTime` 会被当成 UTC 存，与库端 `now()` 差一个时区。）
    只有**日志**用 `nowLocal()` 展示本地时间；`Instant` 加时长直接用 `+ Duration`。
15. **密码用自研 bcrypt**（`util/crypto/BCrypt.kt`，移植 jBCrypt 0.4）：
    - `BCrypt.checkpw(明文, 库里哈希)` 校验、`BCrypt.hashpw(明文, salt)` 计算、`BCrypt.gensalt(rounds = 10)` 生成 salt；
    - 保持 `$2a$` 与 cost=10 语义，**能直接校验库里既有的 `$2a$10$...`**；salt 形如 `$2a$10$` + 22 字符 = 29 字符（取 salt 用 `hash.take(29)`）；
    - ⚠️ `gensalt` 的随机源是 Kotlin 默认 PRNG（`Random.Default`），**非密码学强度**，见 §8 待办；
    - 移植正确性由 **jBCrypt 官方测试向量**锁定：`hashpw("", "$2a$06$DCq7YPn5Rq63x1Lad4cll.")` 必须等于 `$2a$06$DCq7YPn5Rq63x1Lad4cll.TV4S6ytwfsfvkgY8jIucDrjc8deX1s.`（改动算法后先跑这条）。
16. **敏感信息一律不入库**：开发板入口域名、服务器公网 IP、SSH / 数据库账号口令，**都不许写进任何入库文件（含 `doc/`）**。
    - 文档里用占位符：板子入口 `<board-host>`、示例公网 IP 用 RFC 5737 文档网段（如 `203.0.113.10`）、口令 `<board-password>`；
    - 真实值只放**未入库**的 `platforms.json`、隧道 profile、环境变量或板子上的 `application.json`；
    - 已入库过的要连**历史**一起清（重写提交 + `git gc`），别只改当前版本。
17. **业务服务（`service/system/`）的写法**（0.6 收尾定下）：
    - **强类型 DTO，不搬 `Bundle`**：出参在 `dto/SystemDtos.kt`，键名沿用旧版 JSON（`roleType`、`isUse`、分页键 `list`/`rows` 历史不一致也照搬）；
    - **出参永不带 `password`**（旧版回传 bcrypt 哈希，已废弃该行为）；
    - **时间字段是展示串** `yyyy-MM-dd HH:mm:ss`（固定 +08:00，`Instant.toDisplayString()`）——与旧版 `@JsonFormat(timezone="GMT+8")` 逐字一致；**库里仍然是 `Instant`**（约定 14 不变）；
    - **`null` = 不修改**，实现方式是**读-改-写**（读出实体 → 覆盖非空字段 → 整行 `executeUpdateById`）；审计列写 `operatorId ?: 现有值`，别用裸 `operatorId`（会把已有值抹成 NULL）；
    - **服务层不碰 `ctx`**：「谁在操作」用形参 `operatorId: String?` 显式传，控制器从登录态取（0.8 之前一律 `null`）；
    - 批量只能**循环单条**（`@Query` 不支持 `IN`）；`list()` 的 N+1 是这条限制的必然代价。

## 5. 构建 / 验证工作流

### 构建

```powershell
gradlew linkReleaseExecutableMingwX64     # Windows 本地产物 10.7MB
gradlew linkReleaseExecutableLinuxArm64   # 开发板产物 9.4MB
gradlew deploy1m                          # 构建 + 部署到开发板（见 §6）
```

**提交前自检**（防「文件在磁盘上但被 `.gitignore` 吃掉」，见 §7 最后一条）：

```powershell
# 磁盘上有、git 里没有的源文件（.kt/.kts）
$disk = Get-ChildItem -Recurse -Include *.kt,*.kts -File | Where-Object { $_.FullName -notmatch "\\build\\" } |
        ForEach-Object { $_.FullName.Replace("$PWD\","").Replace("\","/") }
$tracked = git -c core.quotepath=false ls-files "*.kt*"   # 必须关掉 quotepath，否则中文路径比较会误报
$disk | Where-Object { $tracked -notcontains $_ }
# 或者直接看被忽略的文件里有没有源码：
git ls-files --others --ignored --exclude-standard | Select-String "\.(kt|kts|sql|json|ts|vue)$"
```

- **Windows 上编译与链接 linuxArm64 都能直接跑**，不需要整包丢给 WSL。唯一缺位的是 `objcopy`（konan 自带的 aarch64 objcopy 是 ELF 二进制、mingw 的 objcopy 不支持 `elf64-littleaarch64`、essentials 版 LLVM 无 `llvm-objcopy`），所以 `objcopyClasspath<目标>` 在 Windows 上**只把这一步借道 WSL**。发行版/用户可用 `classpath { wslDistro / wslUser }` 指定，留空用 WSL 默认值。
- WSL 侧需要 `aarch64-linux-gnu-objcopy`（Ubuntu-24.04 已装，在 `/usr/bin`）。
- 路径转换用 `toWslPath()` 显式转 `/mnt/<盘符>/…`。**不要依赖工作目录传递** —— 从 Windows 进程拉起的 `wsl` 未必能翻译 cwd（实测把 `F:\Develop\…` 传成了 `F:Develop…`）。

### 配置覆盖自测（多级优先级）


### 冒烟（linuxArm64，无需板子）

用 WSL + qemu 跑 Windows 产出的 kexe（依赖：`qemu-user-static`、`libc6-arm64-cross`、`libcrypt.so.1`）：

```bash
KEXE=/mnt/f/Develop/Kotlin/ktor-template/build/bin/linuxArm64/releaseExecutable/ktor-template.kexe
setsid qemu-aarch64-static -L /usr/aarch64-linux-gnu "$KEXE" 7150 > /tmp/ktor.log 2>&1 < /dev/null &
```
> 后台跑**必须** `setsid … < /dev/null &`，否则父脚本退会连带杀掉 qemu，日志里表现为 `JobCancellationException: LazyStandaloneCoroutine is cancelling`，很像协程 Bug 其实不是。

> ⚠️ **接了 sqlx4k 之后，qemu 这条路不能用了**：新版 aarch64 产物在 qemu 下启动即 `SIGSEGV`（`-strace` 显示崩在进程极早期，连一次 `open` 都没有），但**同一个二进制在真机 aarch64 上完全正常**（见 §6 的「临时二进制验机」）。判定为 qemu-user 模拟问题（Rust 静态库/启动早期映射），不是产物问题。**aarch64 的验证以真机为准**；qemu 只适合跑不依赖 sqlx4k 的老产物。

- 板子：`lckfb`（RK3566，aarch64），跑 MariaDB 10.6 + nginx；部署目录 **`/srv/ktor-template`**。

## 7. 历史踩坑速查

| 症状 | 根因 / 处理 |
| --- | --- |
| 编译通过但接口全 404 | KSP 聚合没传源文件 → `Dependencies(aggregating = true, *sourceFiles)` |
| `Unresolved reference 'JvmName'` | `@file:JvmName` 不能进 commonMain → `GenerateConstantsTask` 加 `jvmTarget` 开关 |
| Gradle 报 `input file does not exist` | Gradle 9 对缺失的 `inputs.dir/file` 直接校验失败 → 改 `inputs.files(fileTree(...))` |
| 阿里云镜像缺 Ktor native 产物 | `settings.gradle.kts` 里 `mavenContent { excludeGroupByRegex("io\\.ktor") }` 强制走 mavenCentral |
| `Failed SFTP MKDIR: …/releaseExecutable` | link 任务的 `outputs.files` 是**输出目录**不是文件，hidetake 的 SFTP `put` 对目录会递归 mkdir → 用 `KotlinNativeLink.outputFile` |
| `A problem occurred starting process 'aarch64-linux-gnu-objcopy'` | Windows 上没有可用的 aarch64 objcopy → 借道 WSL（§5） |
| `The plugin is already on the classpath with an unknown version` | buildSrc 引了 KGP 后，主工程必须**无版本**应用 Kotlin 插件（`id("org.jetbrains.kotlin.multiplatform")`） |
| buildSrc 看不到版本目录 | `buildSrc/settings.gradle.kts` 里 `create("libs").from(files("../gradle/libs.versions.toml"))` |
| classpath 里混进垃圾条目 | `ViteJarTask` 产出多一个根目录 `MANIFEST.MF`，并入时排除 |
| JS 上传的字段值带前导 CRLF | multipart 头部结束位置要**逐行扫到空行**，不能用第一个 CRLF |
| Native 上 `receiveMultipart()` 抛异常 | Ktor 3.4 在 Native 未实现 multipart → 自研纯字节解析器（`util/router/Multipart.kt`） |
| 覆盖正在运行的可执行文件失败 | `ETXTBSY` → 先 `mv old old.previous` 再 `mv new` |
| 后台脚本退出后服务跟着死 | `setsid … < /dev/null &`（见 §5） |
| PowerShell 跑 `.ps1` 中文乱码/语法错 | PS 5.1 按 ANSI 读脚本 → 脚本里只用 ASCII，或改文件编码为 UTF-8 BOM |
| PowerShell 里 `$home` 赋值报只读错误 | `$home` 是内置只读变量，换名 |
| `curl -o NUL` 在 Windows 建出名为 `NUL` 的文件 | 用 `-o $null` 或交给 WSL `rm` 删 |
| 磁盘 `application.json` 看着完全没生效 | PowerShell `Set-Content -Encoding UTF8` / 记事本会写 **BOM**，`parseToJsonElement` 直接失败 → 已在解析前剥 BOM，且解析失败会记 WARN（不再静默吞） |
| Koin 4 编译报 `Unresolved reference 'GlobalContext'` / `'koinApplication'` | 这俩在 Koin 4 里**不是公开 API**（`org.koin.mp.KoinPlatform` 属内部），native 上查不到符号 → 只用 `startKoin { }.koin` 并把容器实例显式往下传 |
| 冒烟时 `curl` 返回 7（连不上）但进程活着 | 端口优先级是「命令行 > 环境变量 > 磁盘配置 > 内嵌默认」，先用 `/api/config` 看实际生效端口，别假定 |
| `Could not find sqlx4k-mysql-1.13.1.jar` | 阿里云镜像缺 sqlx4k 的根 jar → `settings.gradle.kts` 里把 `io\.github\.smyrgeorge` 一起 `excludeGroupByRegex`，强制走 mavenCentral（与 `io.ktor` 同理） |
| 加 sqlx4k 后 `Clock.System` / `monthNumber` 编译不过 | sqlx4k 依赖 kotlinx-datetime **0.8.0**，把我们的 0.6.2 顶了上去；0.8 里 `Clock` 迁到 stdlib `kotlin.time.Clock`、`monthNumber/dayOfMonth` 弃用（改 `month.ordinal + 1` / `day`）。依赖被顶版本先用 `gradlew dependencyInsight --dependency kotlinx-datetime --configuration mingwX64CompileKlibraries` 看 |
| 只看到 `Could not create instance for '[Singleton: …]'`，看不到真正的错 | Koin 的 `InstanceCreationException` 把 cause 包住了，而 Kotlin 的 `Throwable.toString()` 不带 cause → 日志已改为渲染整条 cause 链（`Caused by: …`） |
| aarch64 产物在 qemu 里启动即 `SIGSEGV` | qemu-user 模拟问题（崩溃发生在进程极早期、无任何 `open`），同一二进制真机正常 → 改在真机验证（见 §5「临时二进制验机」） |
| MariaDB 报 `1064 ... near '; select id from ...'` | sqlx4k 在 **MySQL 方言**下把生成的 `insert` / `update` 拼成多语句脚本（`insert ...; select ...`）→ 写入改用仓库里的单语句 `@Query`（见 §2-13） |
| 写进库的时间比本地时间差 8 小时 | 实体时间字段用了 `LocalDateTime`：sqlx4k 的 MySQL 连接**会话时区是 `+00:00`**（`select @@session.time_zone` 可验），裸 LocalDateTime 会被当成 UTC 存 → **实体时间字段一律改成 `kotlin.time.Instant`**（驱动按 UTC 往返），问题从类型层面消失（见 §2-14） |
| KSP 报 `Invalid repository method name` / `first parameter must be named 'context'` / `Suspend function cannot override non-suspend` | sqlx4k codegen 的三条硬规则：方法名必须用受支持的前缀、首参必须是 `context: QueryExecutor`、方法必须 `suspend`（见 §2-13） |
| common 代码里引用不到 `XxxRepositoryImpl` | KSP2 在 KMP 下没有 common 编译单元，生成代码只落在目标源集 → 用 `Main.kt` 的 `platformModules()` 注册 |
| KSP 报 `Invalid repository method name 'findAllActive'` / `'countAllByKeys'` | 前缀白名单是**精确匹配**：`findAll`/`deleteAll`/`countAll` 三者要精确，`...By` 只能用 `findAllBy`/`findOneBy`/`deleteBy`/`countBy`/`existsBy`（**没有 `countAllBy`**）→ 改名（如 `countByKeys`、`findAllByDeletedFalse`） |
| 控制器形参报「`XxxRepository` 无法绑定」 | 仓库接口除了 `@Repository` 还要标 `@Injectable`（路由的按类型注入靠它） |
| `in (:ids)` 运行时报 `Illegal parameter data types varchar and row for operation '='` | `@Query` 的占位符在编译期固定，**不支持 `IN (列表)`** → 批量在服务层循环单条方法 |
| 想用「库里既有的 bcrypt 哈希」验收 bcrypt 实现，但没有匹配的明文 | 库里的哈希对应的是**站点登录口令**，不是 SSH/数据库口令（拿 SSH 口令去 checkpw 必然 false）→ 正确做法是先用 **jBCrypt 官方测试向量**锁死算法（见 §2-15），登录链路接通后再用真实账号或自建账号做端到端验收 |
| 源码文件不进库，而 `git status` **毫无提示**（最阴的坑） | `.gitignore` 里通用目录名漏了前导斜线：`log/` 会匹配**任意层级**的 `log` 目录，于是 `src/commonMain/kotlin/moe/lolosia/web/util/log/` 整层被忽略，`Log.kt` 一直没入库，而 `Bootstrap`/`SessionManager`/`CacheManager` 都引用它 → 仓库对 clone 者不可编译。处理：运行目录收紧为 `/log/`、`/work/`（只管仓库根），并在 `.gitignore` 末尾加 `!src/**` 兜底（源码目录一律入库）；提交前用 §5 的自检命令扫一遍 |
| `executeInsert` 拿不到新插入行的自增 id | `execute*` 返回的是**受影响行数**（生成代码注释写明），生成器取自增 id 靠的是 `insert …; select id from … where id = coalesce(nullif(last_insert_id(), 0), ?)` 这条**多语句脚本** —— 而它在 MySQL 方言下正是 `1064` 的成因 → 需要新 id 时**插入后回查**（`RoleService.create` 按 `type + roleName` 取最大 id） |
| 更新后 `updated_by` 变成 NULL | 读-改-写里写了 `updatedBy = operatorId`，而未接登录态时 `operatorId == null`，把库里已有审计值覆盖了 → 一律 `operatorId ?: current.updatedBy`（见约定 17） |
| 前端读 `data.rows` / `data.roleId` / `row.isUse === 1` 全是 undefined | **配套前端副本与 legacy 后端已经漂移**：前端调 `/user/edit`（后端只有 `/user/update`）、调 `/userRole/getByUserId`（后端没这路由）、按「信封把 data 摊平」的假设取字段，而本项目信封是 `{code,msg,data:{…}}`，且 `isUse` 一直是布尔 → 写控制器（0.8）前先跟用户确认以哪边为准 |

  - 「真实账号登录」验收要等登录链路（0.8）接通（或届时自建一个测试账号，用我们自己的 `hashpw` 写库再登录，形成闭环）。**bcrypt 与业务已打通**：`/api/svc/selftest` 里「建用户 → 改密码（验旧密码）」实跑通过。
- **`RoleService.create` 的自增 id 靠回查**：`executeInsert` 只回受影响行数（§7），目前按 `type + roleName` 取最大 id。若以后要更稳，可考虑给角色 id 改应用侧生成（影响既有 1~5 号角色的引用，需评估）。
- **测试**：`legacy/jvm/test/kotlin/ServerTest.kt` 未迁移，native 侧 `commonTest` 只有依赖声明、**零测试**；目前验证全靠临时冒烟脚本（未入库，可考虑收进 `src/nativeTest` 或 `doc`）。
- **`classpath.zip` 只支持 STORED**（未实现 DEFLATED），release 里约 5MB 是这个 zip；改 DEFLATED 需补 `platform.zlib` inflate。属可选优化。
- **产物体积**：mingwX64 release 从 10.7MB 涨到 **12.6MB**（接入 koin-core / okio / kotlinx-datetime 的 klib 代码），属 0.5 的预期代价。
- 前端 `vite*.ts` 会连 `vitest.config.ts` / `vitest.setup.ts` 一起匹配，改测试配置也会触发一次 vite 构建；收紧可写 `vite.config*.ts`。
