# 开发记忆（Ktor 模板 → Kotlin/Native）

> 用途：**会话交接记忆**。换 session / 换设备后先读本文，再按需查详细方案。
> 详设与实测记录见 [native-migration-plan.md](./native-migration-plan.md)（§8 = P0/P1/P2 路线，§13 = 实施进度与踩坑）。
> 分支：`native`。所有内容以**实测**为准，未经验证的推断已剔除。

## 1. 项目概览

- 原本是 Ktor **JVM** 单体后端模板（`project-template`），现在整体迁往 **Kotlin/Native**，只产出**原生可执行文件**。
- 目标平台：**`mingwX64`**（Windows 本地开发调试）+ **`linuxArm64`**（部署到开发板）。**不保留 JVM 目标**。
- 旧 JVM 代码**整体移到 `legacy/`**（不参与编译，仅作移植参考）；`:orm` 模块与全部 JVM 插件/依赖已移除。
- 根包 **`moe.lolosia.web`**；独立 Gradle 模块 `:router-ksp`（包名保持 `moe.lolosia.router.ksp`，它是插件域，不受根包约束）。
- 配套前端工程：`F:\Develop\Node\lolosia-web`（Vue3 + Vite），已通过 `platforms.json` 的 `webPath` 接入构建。

## 2. 硬性约定（改动前必读，违反会返工）

1. **包归置**：`src/` 下代码一律 `moe.lolosia.web`。
   - 工具/脚手架进 `util.<域>`：`util.router`（注解+参数绑定+multipart）、`util.classpath`（资源访问）、`util.session`（上下文）
   - `controller/` 放控制器；`buildSrc` 的 Gradle 插件包名不受此限
2. **按类型自动注入（Spring 风格）**：控制器形参写 `ctx: Context`，**不加任何注解前缀**（曾有过 `@Attribute("ctx")`，已按要求移除）。
   路线：类型标 `@Injectable` → 启动时 `RouterInjection.register(类型) { call -> ... }` → KSP 生成 `call.inject<T>()`。
3. **注解参数名可省略**：`@Path` / `@Query` / `@Header` / `@Form` / `@FilePart` 不写名字时默认取形参名。
4. **资源一律走 `classpath` 中间层**，不要用文件系统路径：
   `src/<sourceSet>/resources/**` 就是 classpath 根，运行时 `classpath.read("static/home/index.html")`，与 Java 打资源文件完全一致。
5. **控制器跨项目复制的目标是"只改 import"** —— 注解同名同义，方法体零改动。
6. **`main()` 必须放各目标源集**：KSP2 在 KMP 下**没有 common/metadata 编译单元**，生成代码落在目标源集，而 common 代码看不到 platform 声明。故 common 提供 `startServer(port) { generatedRoutes() }`，各目标 `main()` 传入。
7. **KSP 聚合输出必须带源文件**：`Dependencies(aggregating = true, *sourceFiles)`。只写 `aggregating = true` 会导致增量处理漏扫未改动文件里的 `@Controller`，症状是**编译通过但接口全 404**。
8. **前端路径不许写死**：用 `generateConstants` 产出的 `VITE_DEFAULT`（值 = viteJar 的 `contextPath`）拼路由。
9. **构建/部署只有一个入口**：Windows 上 `gradlew deploy1m`（见 §5）。
10. **配置只认 `AppConfig` 一个入口**：`moe.lolosia.web.config.AppConfig`（`@Serializable` 数据类）。
    加载优先级（低→高）：数据类默认值 < classpath 内嵌 `src/commonMain/resources/application.json` < 磁盘 `application.json`（CWD，systemd 下 = `/srv/ktor-template/`）< 环境变量（`KTOR_HOST/PORT/LOG_LEVEL/DB_URL/DB_USERNAME/DB_PASSWORD`）；端口另可由命令行参数覆盖（最高）。
    各层按字段深合并。加配置项 = 改数据类 + 可能改 `envOverrides`，**不要另起一套读取逻辑**。
11. **日志一律走 `Log.of("tag")`**，不要 `println`；级别由配置 `logLevel` 控制。
12. **DI：Koin 容器显式传递，不要碰全局容器**。`startAppKoin(config, cp)` 返回 `Koin` 并向下传；
    容器里的实例用 `koin.registerInjectable<T>()` 接进路由「按类型注入」，控制器形参声明即得。
    ⚠️ Koin 4 里 `org.koin.core.context.GlobalContext` 与 `koinApplication` **不是公开 API**（native 上直接 Unresolved），只有 `startKoin { }.koin` 可用。

**原先挡在路上的两块已在 0.5 定案**：

- **配置系统**（原为空缺）：改为 `@Serializable` `AppConfig` + JSON 多级覆盖（见 §2-10）。DB 地址、密钥、端口都有落点；服务器上改磁盘 `application.json` 即可，不必重编二进制。
- **Service 层 DI**：选 **Koin 4.2.2**（native 产物已核实齐全），容器实例显式传递 + `registerInjectable<T>()` 接进路由按类型注入（见 §2-12）。0.6 起的服务按 `single { XxxService(get()) }` 挂进 `appModule`。
- **日志**：自研极简实现（级别 + 时间戳 + 异常栈），理由：需求只有三样、KMP 日志库在 native 上的时间戳能力都不明确。

**建议顺序**：0.6 → 0.7 → 0.8（0.1~0.5、0.9 已完成）。

## 5. 构建 / 验证工作流

### 构建

```powershell
gradlew linkReleaseExecutableMingwX64     # Windows 本地产物 10.7MB
gradlew linkReleaseExecutableLinuxArm64   # 开发板产物 9.4MB
gradlew deploy1m                          # 构建 + 部署到开发板（见 §6）
```

- **Windows 上编译与链接 linuxArm64 都能直接跑**，不需要整包丢给 WSL。唯一缺位的是 `objcopy`（konan 自带的 aarch64 objcopy 是 ELF 二进制、mingw 的 objcopy 不支持 `elf64-littleaarch64`、essentials 版 LLVM 无 `llvm-objcopy`），所以 `objcopyClasspath<目标>` 在 Windows 上**只把这一步借道 WSL**。发行版/用户可用 `classpath { wslDistro / wslUser }` 指定，留空用 WSL 默认值。
- WSL 侧需要 `aarch64-linux-gnu-objcopy`（Ubuntu-24.04 已装，在 `/usr/bin`）。
- 路径转换用 `toWslPath()` 显式转 `/mnt/<盘符>/…`。**不要依赖工作目录传递** —— 从 Windows 进程拉起的 `wsl` 未必能翻译 cwd（实测把 `F:\Develop\…` 传成了 `F:Develop…`）。

### 冒烟（本机 mingw）

```powershell
$exe = "build\bin\mingwX64\releaseExecutable\ktor-template.exe"
$p = Start-Process $exe -ArgumentList 7160 -PassThru
Start-Sleep 4
curl.exe -s http://127.0.0.1:7160/api/ping          # pong
curl.exe -s http://127.0.0.1:7160/api/whoami        # uri=/api/whoami（ctx 自动注入）
curl.exe -s http://127.0.0.1:7160/api/config        # port=7160, db=..., logLevel=INFO（配置 + Koin→注入链路）
curl.exe -s "http://127.0.0.1:7160/api/user/get/42?verbose=true"
curl.exe -s -X POST http://127.0.0.1:7160/api/echo -H "Content-Type: application/json" -d '{\"name\":\"a\",\"times\":3}'
curl.exe -s -X POST http://127.0.0.1:7160/api/upload -F note=hello -F file=@src/commonMain/resources/hello.txt
curl.exe -s -o "$env:TEMP\curl.out" -w "%{http_code} %{size_download}`n" http://127.0.0.1:7160/home/   # 200 + 前端首页
Stop-Process -Id $p.Id
```
> 期望：日志首行 `classpath 已装载：87 个条目（来源：可执行文件内嵌 zip）`，格式为 `[时间] [级别] [tag] 消息`，且 `Uncaught Kotlin exception` 计数为 0。
> 注意 `curl -o $null` 在 PowerShell 里不会真的丢弃输出（会打到控制台），要落盘就写 `"$env:TEMP\curl.out"`。

### 配置覆盖自测（多级优先级）

```powershell
$cfg = "$env:TEMP\ktor-cfg-test"; New-Item -ItemType Directory -Force $cfg | Out-Null
# 故意用带 BOM 的写法（PS 5.1 的 -Encoding UTF8 会写 BOM），验证 BOM 容忍

$p = Start-Process $exe -ArgumentList 7163 -WorkingDirectory $cfg -PassThru; Start-Sleep 4
curl.exe -s http://127.0.0.1:7163/api/config          # 命令行赢环境变量：port=7163
Stop-Process -Id $p.Id -Force; Remove-Item Env:KTOR_PORT
```

### 冒烟（linuxArm64，无需板子）

用 WSL + qemu 跑 Windows 产出的 kexe（依赖：`qemu-user-static`、`libc6-arm64-cross`、`libcrypt.so.1`）：

```bash
KEXE=/mnt/f/Develop/Kotlin/ktor-template/build/bin/linuxArm64/releaseExecutable/ktor-template.kexe
setsid qemu-aarch64-static -L /usr/aarch64-linux-gnu "$KEXE" 7150 > /tmp/ktor.log 2>&1 < /dev/null &
```
> 后台跑**必须** `setsid … < /dev/null &`，否则父脚本退会连带杀掉 qemu，日志里表现为 `JobCancellationException: LazyStandaloneCoroutine is cancelling`，很像协程 Bug 其实不是。

### vite 前端的增量行为

- `viteJar` 的 `inputs` 由 `lolosia { viteJar { platform(...) { cache { } } } }` 的 `dirs=["src","typings","public"]` / `files=["package.json"]` / `filePatterns=["vite*.ts"]` 声明，**增量是好的**。
- **改 `buildSrc` 会让所有 task 失效**（Gradle 把任务实现的 classloader hash 算进 up-to-date 判定），表现为"每次构建都重跑 vite"。改完 buildSrc 后看到的频繁重跑属正常现象，不是 bug。

## 6. 部署与开发板

- 板子：`lckfb`（RK3566，aarch64），跑 MariaDB 10.6 + nginx；部署目录 **`/srv/ktor-template`**。
- 现网 JVM 版与原生版**并行**，可对照/回滚：
  | | 单元 | 端口 | 产物 |
  | --- | --- | --- | --- |
  | JVM（现网） | `ktor-template.service` | 7129 | `ktor-template-1.0.0-SNAPSHOT-fat.jar` |
  | 原生（新） | `ktor-template-native.service` | 7130 | `ktor-template`（+ `.previous` 回滚文件） |
- `platforms.json`（**已 gitignore，不提交**）配 `webPath` 与服务器；原生部署靠服务器上的 `"abi": "arm64"` 开启（不配 = 走 JVM fat jar）。
- **`host` 必须写 `127.0.0.1`，不要写 `localhost`**：Windows 上 `localhost` 会先解析到 `::1`，而隧道只绑 IPv4。
  > 原生服务的 `host = "0.0.0.0"` 只绑 IPv4，从外部用板子的 **IPv6** 探 7130 会失败（JVM/Netty 默认双栈，所以 7129 探得通）。要 IPv6 直连就把监听地址改成 `::`。

### 两条到板子的路

**A. 隧道（默认，`platforms.json` 里就是它）**

```powershell
cd F:\Develop\Python\quic-socket
.\.venv\Scripts\python.exe client.py --config "<配置 yaml>"
```
- QUIC 代理客户端，转发 `127.0.0.1:6023 → localhost:22`、`127.0.0.1:3307 → localhost:3306`。
- 配置可取自 GUI 存的 profile：`QuicSocketClient\bin\Debug\net10.0-windows\work\servers\<board-host>.json`（schema 与 `client.py` 一致，可直接当 yaml 用），或复制该 profile 到 `%TEMP%\quic-1m-board.yaml`。
- 隧道带宽较低，传 9.4MB 产物明显慢。

**B. 直连板子公网 IPv6（部署提速用）**

```powershell
curl.exe -s http://<board-host>/ipv6        # 返回板子的 `ip addr`，取 eth0 的全球 IPv6
```
临时把 `platforms.json` 的 `host` 改成该 IPv6、`port` 改成 `22`，部署完**记得改回 `127.0.0.1:6023`**。
> 板子的 IPv6 会变（多个 SLAAC 地址），不要写死在文档/代码里。

### 在 Windows 侧带密码 SSH（调试用）

`ssh` 需要交互输密码，用 `SSH_ASKPASS` 可自动化（Windows OpenSSH 9.5 实测可用）：

```powershell
Set-Content -Path "$env:TEMP\askpass.cmd" -Value "@echo <密码>" -Encoding ASCII   # 密码见本地 platforms.json
$env:SSH_ASKPASS = "$env:TEMP\askpass.cmd"; $env:SSH_ASKPASS_REQUIRE = "force"; $env:DISPLAY = "localhost:0"
ssh -n -o StrictHostKeyChecking=no -o UserKnownHostsFile=NUL -p 6023 <user>@127.0.0.1 "systemctl is-active ktor-template-native.service"
```
> WSL 里的 `sshpass` **够不到 Windows 侧的隧道**（NAT 模式 + 防火墙拦入站，连宿主已监听 `0.0.0.0` 的 mysqld 都连不上）；WSL 也没有 IPv6 路由，所以也连不上直连地址。

## 7. 历史踩坑速查

| 症状 | 根因 / 处理 |
| --- | --- |
| 编译通过但接口全 404 | KSP 聚合没传源文件 → `Dependencies(aggregating = true, *sourceFiles)` |
| `Unresolved reference 'JvmName'` | `@file:JvmName` 不能进 commonMain → `GenerateConstantsTask` 加 `jvmTarget` 开关 |
| Gradle 报 `input file does not exist` | Gradle 9 对缺失的 `inputs.dir/file` 直接校验失败 → 改 `inputs.files(fileTree(...))` |
| 阿里云镜像缺 Ktor native 产物 | `settings.gradle.kts` 里 `mavenContent { excludeGroupByRegex("io\\.ktor") }` 强制走 mavenCentral |
| `Failed SFTP MKDIR: …/releaseExecutable` | link 任务的 `outputs.files` 是**输出目录**不是文件，hidetake 的 SFTP `put` 对目录会递归 mkdir → 用 `KotlinNativeLink.outputFile` |
| `A problem occurred starting process 'aarch64-linux-gnu-objcopy'` | Windows 上没有可用的 aarch64 objcopy → 借道 WSL（§5） |
| `The plugin is already on the classpath with an unknown version` | buildSrc 引了 KGP 后，主工程必须**无版本**应用 Kotlin 插件（`id("org.jetbrains.kotlin.multiplatform")`） |
| buildSrc 看不到版本目录 | `buildSrc/settings.gradle.kts` 里 `create("libs").from(files("../gradle/libs.versions.toml"))` |
| classpath 里混进垃圾条目 | `ViteJarTask` 产出多一个根目录 `MANIFEST.MF`，并入时排除 |
| JS 上传的字段值带前导 CRLF | multipart 头部结束位置要**逐行扫到空行**，不能用第一个 CRLF |
| Native 上 `receiveMultipart()` 抛异常 | Ktor 3.4 在 Native 未实现 multipart → 自研纯字节解析器（`util/router/Multipart.kt`） |
| 覆盖正在运行的可执行文件失败 | `ETXTBSY` → 先 `mv old old.previous` 再 `mv new` |
| 后台脚本退出后服务跟着死 | `setsid … < /dev/null &`（见 §5） |
| PowerShell 跑 `.ps1` 中文乱码/语法错 | PS 5.1 按 ANSI 读脚本 → 脚本里只用 ASCII，或改文件编码为 UTF-8 BOM |
| PowerShell 里 `$home` 赋值报只读错误 | `$home` 是内置只读变量，换名 |
| `curl -o NUL` 在 Windows 建出名为 `NUL` 的文件 | 用 `-o $null` 或交给 WSL `rm` 删 |
| 磁盘 `application.json` 看着完全没生效 | PowerShell `Set-Content -Encoding UTF8` / 记事本会写 **BOM**，`parseToJsonElement` 直接失败 → 已在解析前剥 BOM，且解析失败会记 WARN（不再静默吞） |
| Koin 4 编译报 `Unresolved reference 'GlobalContext'` / `'koinApplication'` | 这俩在 Koin 4 里**不是公开 API**（`org.koin.mp.KoinPlatform` 属内部），native 上查不到符号 → 只用 `startKoin { }.koin` 并把容器实例显式往下传 |
| 冒烟时 `curl` 返回 7（连不上）但进程活着 | 端口优先级是「命令行 > 环境变量 > 磁盘配置 > 内嵌默认」，先用 `/api/config` 看实际生效端口，别假定 |

  - `sqlx4k 1.13.1` 的 klib 由 **Kotlin 2.4.10** 编译（本工程 2.4.0），能否直接消费需实测；
  - `mingwX64` 上若报 `lld-link: error: -exclude-symbols:___chkstk_ms is not allowed in .drectve`（库官方 issue #18，已关闭），用 `freeCompilerArgs.add("-Xoverride-konan-properties=linker.mingw_x64=<LLVM>/bin/ld.lld")` 绕。
  - MySQL 方言下 `batchInsert`/`batchUpdate` **不可用**（缺 `RETURNING`），MariaDB 方言库还没实现。
- **0.7 bcrypt 须自研**：移植 jBCrypt（Blowfish/EksBlowfish）到 commonMain，纯 Kotlin 无平台依赖；验收 = 用库里现存 `$2a$10$...` 哈希直接校验通过。
- **测试**：`legacy/jvm/test/kotlin/ServerTest.kt` 未迁移，native 侧 `commonTest` 只有依赖声明、**零测试**；目前验证全靠临时冒烟脚本（未入库，可考虑收进 `src/nativeTest` 或 `doc`）。
- **`classpath.zip` 只支持 STORED**（未实现 DEFLATED），release 里约 5MB 是这个 zip；改 DEFLATED 需补 `platform.zlib` inflate。属可选优化。
- **产物体积**：mingwX64 release 从 10.7MB 涨到 **12.6MB**（接入 koin-core / okio / kotlinx-datetime 的 klib 代码），属 0.5 的预期代价。
- 前端 `vite*.ts` 会连 `vitest.config.ts` / `vitest.setup.ts` 一起匹配，改测试配置也会触发一次 vite 构建；收紧可写 `vite.config*.ts`。
